# 部署说明（内网服务器 · 独立环境 data_label）

## 为什么是"独立环境"

**本平台固定部署在 `10.2.248.6`；数据挖掘在 `10.2.248.34`，是两台机器，天然隔离。**

| | data_label（本项目） | data_mining（数据挖掘） |
| --- | --- | --- |
| 机器 | **`10.2.248.6`** | `10.2.248.34` |
| 部署目录 | `/opt/data_label` | `/opt/ad_mining` |
| 服务名 | `data_label.service` | `ad_mining.service` |
| 系统账号 | `data_label`（专用，不在别处复用） | root + Python venv |
| 端口 | `3001`（对外经 nginx **80**） | 8009（对外经 nginx 80） |
| 数据库 | MySQL 8 库 `data_label` + 专用账号 | SQLite（`workspace/mining.db`） |
| 运行时 | 自带 Node 放在 `/opt/data_label/runtime`（不装系统级 Node） | `/venv`（Python） |

服务器：**`10.2.248.6`**，登录账号 `algo`（密码认证）。

访问地址：**http://10.2.248.6/**（nginx 反代到应用端口 3001；重定向/上传限制都已配好）

> 数据挖掘部署在 `10.2.248.34`（`ad_mining.service`、8009、SQLite）。本平台在**另一台机器**上，目录/账号/数据库/端口全独立，两边互不影响。

## 一键部署

```bash
# 项目根目录，Windows 本机执行
node scripts/deploy-to-server.mjs --user algo --password 123

# 密码放环境变量，避免进命令历史
DEPLOY_SSH_PASSWORD=123 node scripts/deploy-to-server.mjs --user algo

# 只探测服务器环境（不改动任何东西）：OS、sudo、MySQL、端口占用、磁盘、外网
node scripts/deploy-to-server.mjs --check-only --user algo --password 123

# 本地构建打包，打印远端步骤，不连接服务器
node scripts/deploy-to-server.mjs --dry-run
```

`npm run deploy` / `npm run check:server` 是前两条的快捷方式（默认用户已是 `algo`）。

常用参数：`--port`、`--dir`、`--service`、`--run-user`、`--db`、`--db-user`、`--node-version`、`--skip-tests`、`--no-restart`、`--force-seed`。

### 脚本做了什么

1. 本地跑单测 + `npm run build`；打包 `dist/ server/ scripts/ deploy/ package*.json`（**不含** `.env`、`node_modules`、`uploads/`、`server/data`、tests）；
2. 用 ssh2 连服务器（密码或密钥），先探测环境：是否有 systemd、MySQL 客户端、目标端口是否被占、磁盘、外网连通性；
3. 建专用系统账号 `data_label`（`useradd --system`，不可登录、无家目录），建 `/opt/data_label`；
4. **先备份**已有 `/opt/data_label` 到 `/root/data_label-backup-*.tar.gz`；
5. 准备自带 Node 运行时：系统 Node ≥ 20 就用系统的，否则从 nodejs.org 下 `node-v20.18.1-linux-x64` 解到 `/opt/data_label/runtime`（不写系统环境）；
6. 解包代码（不动 `.env`/`uploads`/`runtime`）→ 用自带 npm 执行 `npm ci --omit=dev`；
7. 首次部署才做：生成 `.env`（`JWT_SECRET`、数据库密码用 `openssl rand` 在服务器本地生成）→ 执行 `deploy/init-db.sql` 建库 `data_label` 和专用账号；
8. 导入账号与供应商名册（`scripts/seed-db.mjs`，默认"空则填"，不会覆盖服务器上已改的账号）；
9. 安装 `data_label.service` → `chown data_label` → `systemctl enable --now`；
10. 健康检查 `http://127.0.0.1:3001/api/health`，失败自动打 `journalctl`；成功后打印隔离确认（`ad_mining` 与 `data_label` 各自状态）。

### 权限前提

安装 systemd 单元、建系统账号、建库都需要 root。脚本走 `sudo -S` 用同一个密码提权，所以 **`algo` 需要有 sudo 权限**。如果 `--check-only` 里显示 `sudo: 需要密码`，那就是需要密码也能用（脚本会喂密码）；若显示 sudo 不可用，请让运维给 `algo` 加 sudo 或改用 root 部署（`--user root --key ...`）。

## 运维命令

```bash
systemctl status data_label            # 状态
systemctl restart data_label           # 重启（改后端代码后必须重启）
journalctl -u data_label -f            # 实时日志
journalctl -u data_label -n 100        # 最近 100 行
curl -s localhost:3001/api/health      # 健康检查
```

确认没有影响数据挖掘：

```bash
systemctl is-active ad_mining data_label     # 两个都应 active
ss -lntp | grep -E ':(3001|8009)'
```

回滚：

```bash
ls -t /root/data_label-backup-*.tar.gz | head -1
tar xzf /root/data_label-backup-<时间戳>.tar.gz -C /opt/data_label
systemctl restart data_label
```

## 账号与数据

- **账号不会带演示账号上线**：`server/repositories/data.js` 内置了 `taixing/123`、`supp_a/123` 之类演示账号，干净库启动时会被塞进内存。所以部署时导入 `deploy/seed.json`（25 个真实账号 + 3 家供应商名册 + 飞书配置 + 场景维度）。`npm run seed:export` 导出、`npm run seed:import` 导入。
- **业务数据不带过去**：种子里的业务集合一律空数组；历史单据需要的话用 `mysqldump` 单独导。
- 种子含密码哈希，已在 `.gitignore` 里（`deploy/seed.json`、`deploy/.build/`），不要提交。

## 手工部署（不用脚本时）

```bash
# 本地
npm run build
tar czf /tmp/data-label.tar.gz --exclude=server/data --exclude=node_modules --exclude=.env --exclude=uploads \
    dist server scripts deploy package.json package-lock.json
```

传到服务器后（以 root 执行）：

```bash
useradd --system --no-create-home --shell /usr/sbin/nologin data_label
mkdir -p /opt/data_label/uploads/bills && tar xzf /tmp/data-label.tar.gz -C /opt/data_label
cd /opt/data_label
# 自带 Node（可选，也可用系统 Node 20）
curl -fsSL https://nodejs.org/dist/v20.18.1/node-v20.18.1-linux-x64.tar.xz | tar xJ -C /opt/data_label/runtime --transform 's|^[^/]*|node|'
./runtime/node/bin/npm ci --omit=dev
cp deploy/env.production.example .env && vi .env      # JWT_SECRET(openssl rand -hex 32)、DB_PASSWORD、CORS_ORIGIN
sed -i "s|REPLACE_WITH_STRONG_PASSWORD|<上面的DB_PASSWORD>|" deploy/init-db.sql && mysql -uroot < deploy/init-db.sql
./runtime/node/bin/node scripts/seed-db.mjs
sed -e "s|/usr/bin/node|/opt/data_label/runtime/node/bin/node|" deploy/data-label.service > /etc/systemd/system/data_label.service
chown -R data_label:data_label /opt/data_label && chmod 600 .env
systemctl daemon-reload && systemctl enable --now data_label
```

## 备份与巡检（已上线，2026-09-18）

### 备份（/etc/cron.d/data-label-backup，每天 02:30）

`deploy/backup-db.sh`（v2）一次备份三样到 `/root/backup`：MySQL 全库（不锁表）、`uploads/` 附件、`.env` 配置（权限 600）；随后 **rsync 异地容灾到 10.2.248.34**（`/home/algo/data_label_backup`，保留 90 天）。本地保留 14 天。

异地通道安全设计：`.6` 用专用密钥 `/root/.ssh/data_label_backup_key` 免密推送；`.34` 侧 `authorized_keys` 对该密钥加了**强制命令**（`/home/algo/data_label_backup/receive.sh`）——只允许 rsync 推送到备份目录、两条精确的 ls 查询和过期清理，其他任何命令一律 `DENIED`。

### 健康巡检（/etc/cron.d/data-label-monitor，每 5 分钟）

`deploy/health-monitor.sh` 检查：API 健康、MySQL 状态、磁盘水位（85%）、**写入降级**（MySQL 写失败会静默回退本地 db.json，靠文件 mtime 发现）、本地/异地备份新鲜度（26 小时）、app_state 体量（5MB 预警）、服务内存（1200MB 预警）。异常时读 `feishuConfig` 的 webhook 发飞书告警，同一告警 1 小时内最多一条，恢复后补一条恢复通知。

手动测试：`MONITOR_DRYRUN=1 sudo /opt/data_label/deploy/health-monitor.sh`（只打印不发送）；`MONITOR_FORCE=api sudo ...`（强制触发一条真实测试告警）。

### 灾备恢复要点

1. 解开最近的 `data_label-env-*.tar.gz` 恢复 `.env`；
2. `gunzip < data_label-*.sql.gz | mysql -uroot data_label` 恢复数据库；
3. 解开 `data_label-uploads-*.tar.gz` 恢复附件到 `/opt/data_label/uploads`；
4. 重装服务（见上文部署步骤 9-10）。

### ⚠ 运维红线：改动 app_state 里的 JSON 集合

`app_state.data` 是 JSON 列，集合里含大量中文。**不要在 shell 里把 JSON 直接拼进 SQL**——
经 ssh/heredoc/命令替换后，Unicode 转义（反斜杠 + uXXXX）会被吃掉反斜杠，
导致中文被写成 `u5eb7u5c3c...` 这样的字面量（2026-09-21 曾因此写坏过 users 集合，靠备份恢复）。

正确做法（二选一）：
1. **hex/base64 全程无损传输**（推荐）：
   ```bash
   # 读：base64 编码后回本地解析
   mysql -N -B data_label -e "SELECT data FROM app_state WHERE name='users'" | base64 -w0
   # 写：本地生成 JSON → hex → 服务器解码后直接赋值（纯 ASCII，零转义风险）
   mysql data_label -e "UPDATE app_state SET data = CONVERT(UNHEX('<hex>') USING utf8mb4) WHERE name='users'"
   ```
2. **走界面/接口**：账号与角色请在「用户管理」页操作，不要手改 SQL。

改动前务必先备份：
`mysql -N -B data_label -e "SELECT data FROM app_state WHERE name='users'" > /tmp/users-$(date +%F-%H%M%S).json`
