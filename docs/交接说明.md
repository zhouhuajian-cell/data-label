## 二、业务主线：验收结算确认流（7 环节）

```
供应商上传(导入解析明细+附件+成本中心金额)
  → 财务指派业务工程师（可改派）
  → 业务工程师确认
  → 财务确认（先核算：扣款/税率→应付金额）
  → 统结方(柏川) 导入统结明细+附件 提交
  → 财务二次确认（同项目+同周期：供应商合计 vs 统结方提交，增幅 >3.5% 报警并拦截）
  → 负责人确认 → 算法确认 → OA结算专员确认 → 已通过
```

- **状态机唯一权威**：`server/lib/bill-flow.js` 的 `BILL_STAGES` + `deriveStatus(currentStage, rejected)`；**禁止"任意改 status"的接口**
- **驳回 = 整单退回供应商**，修正后重新提交，确认链从第一环节重走；链路进度**只认当前轮**（`resubmitCount` 轮次，确认记录带 `round`）
- **金额口径**：明细字段 `数量 / 单价（RMB）/ 总金额（RMB）`；金额支持 **10 位小数**（`server/lib/money.js` 的 `roundMoney`，比率仍 2 位）；DB 列为 `DECIMAL(28,10)`，启动时自动升级
- **成本中心**：填**金额**，占比自动算；金额合计必须等于单据总金额（统结方选填）
- **姓名口径**：供应商身份 = `bill.supplierName` ↔ 账号 `userName`（**已彻底废弃"归属供应商 supplierId"逻辑**）
- **消息口径**：所有提醒/待办按「角色-姓名」（如 `业务工程师-罗桂林`），提醒不展示金额

## 四、本会话修过的问题（避免重犯）

1. **归属供应商逻辑删除**：改成姓名口径（`supplierName` ↔ `userName`），JWT/用户管理/建单/隔离/汇总全部去 `supplierId`
2. **统结对比未落库**：`bills_finance.comparison` 列（财务一重启就看不到对比结果）
3. **改派后原工程师仍见待办**：`isMyTurn` 改为"第一环节按被指派人"，并清理原处理人待办 + 发「已改派」
4. **驳回后改金额被拦**：`updateBill` 里"成本中心校验"跑在"按新明细重算合计"之前 → 顺序调换
5. **重提后链路显示上一轮"已通过"**：确认记录加 `round`，链路只认当前轮；老记录无 `round` 时按当前轮计（否则老单据链路变空）
6. **附件引用正则漏 `doc/docx`**（白名单加了但正则没加，带 Word 附件提交 422）→ 正则由 `ATTACH_EXTS` 自动生成
7. **明细合计行没有总金额**：`el-table-column` 缺 `prop="amount"`，`show-summary` 算不出
8. **统结对比把不同批次累加**：口径改为「同项目 + 同结算周期」，结算周期改必填（且界面显示对比口径）
9. **供应商之间能看到彼此的项目**：项目列表/详情/下拉/改/删/归档全部加供应商归属校验；**并修 `createProject` 未写 `createdBy`**（否则新建项目建完不可见 = 看起来"创建不了"）
10. **金额显示带浮点噪声**（`…9500000002`）：`formatMoney` 与两位小数差 <1e-8 按两位显示，真精度才展开
11. **部署了但界面还是旧的**：nginx 未设缓存策略，入口 HTML 被缓存 → 现为入口/接口 `no-store`、`/assets/*` 长缓存
12. **工程教训**：
    - 本项目文件**行尾混用**（有的 CRLF 有的 LF）→ 文本替换要 LF/CRLF 两种都试
    - **不要用正则/切块方式改大段代码**：曾切坏 `server/services/bills.js` 尾部约 700 行（该项目文件当时无 git 记录），靠 `.bak/bills.js.pre-compare` 重建
    - python heredoc 里 `\n`、`\\$` 易被 shell/转义搞坏 → 含转义的代码用 Write 工具写文件，再 `node --check` 立即验证
