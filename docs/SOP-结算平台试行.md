## 一、平台定位

平台解决一件事：**把"已验收数据的结算"从口头/微信/表格确认，变成有痕迹、有节点、有校验的线上流程**。

三条主线：

1. **结算单线上确认**：供应商上传 → 业务工程师 → 财务 → 统结方提交 → 财务二次确认 → 负责人 → 算法 → OA 结算，共 7 个环节，逐环留痕。
2. **数据仪表盘**：按供应商、成本中心、结算周期汇总累积结算金额与分布，随时可查。
3. **留痕可追溯**：谁在什么时候确认/驳回、附件、金额核算过程全部留档，可导出对账明细。

**试行目标**：让 7 个环节各自按线上流程走完一个完整结算周期，验证流程与口径是否符合实际业务，再决定全面推广。

## 三、结算流程（7 环节）

```
供应商上传/导入 →  业务工程师 →  财务 →  统结方提交 →  财务二次确认 →  负责人 →  算法 →  OA 结算
   ①建项目+导入       ②数据确认    ③核算确认    ④导入统结数据     ⑤汇总对比      ⑥复核    ⑦确认   ⑧OA收尾
```

| 环节 | 谁做 | 必须完成的事 | 系统校验（不满足则提交不了） |
| --- | --- | --- | --- |
| ① 上传 | 供应商 | 选项目 → 导入明细表（Excel/CSV/粘贴）→ 填**成本中心金额** → 上传明细附件 → 提交 | 明细非空；成本中心金额合计 **=** 单据总金额；附件必须上传 |
| ② 业务工程师 | 财务先指派的那一位 | 核对验收明细、成本中心与金额后确认 | 未指派工程师不能确认；非被指派人也确认不了 |
| ③ 财务 | 张海霞 | 逐单核算：填扣款、税率 → 系统算应付金额 → 确认 | 未核算不能确认；金额较供应商提交额增幅 **> 3.5%** 拦截并报警 |
| ④ 统结方 | 柏川 | 导入自己这一期的统结数据（明细表），系统自动汇总金额 → 提交 | 未导入不能提交 |
| ⑤ 财务二次确认 | 张海霞 | 看汇总对比（供应商合计 / 统结方提交 / 差额 / 增幅），在限内确认 | 增幅 **> 3.5%** 拦截并报警；超限时需统结方改正后重新提交 |
| ⑥ 负责人 | 蔡家辉 | 复核确认 | 同上（金额增幅超限不可确认） |
| ⑦ 算法 | 马成男 | 确认 | 同上 |
| ⑧ OA 结算 | 彭桂苹 | 在 OA 系统完成最新结算后，回平台确认 | —— |

**确认完成**后系统自动：回执供应商与甲方 PM、抄送统结方、通知 OA 结算专员。

### 关键口径（统一口径，避免争议）

| 口径 | 规定 |
| --- | --- |
| 明细字段 | 序号 / 项目 / 单位 / **数量** / **单价（RMB）** / **总金额（RMB）** |
| 金额 | 单价 × 数量，保留到小数点后 10 位（不做两位截断）；金额取"应付金额"口径 |
| 成本中心 | **填金额**，占比由金额自动计算；金额合计必须等于单据总金额 |
| 增幅红线 | **3.5%**：单张单据（③）、供应商合计 vs 统结方提交（⑤）两处校验 |
| 驳回 | 任一环节驳回 = **整单退回供应商**，修正后重新提交，确认链从第一环节重走 |

## 四、各角色操作步骤

### 4.1 供应商（壹莱倍 / 莱斯博）

1. 登录 → 左侧「**项目管理**」→ 新建项目（填项目名称；业务类型默认"标注"，数据类型可不填）或选择已有项目
2. 在项目下点「**上传验收数据**」
3. 明细：用「Excel/CSV 导入」（建议先下载模板）或「粘贴导入」；核对解析结果
4. **成本中心金额**：下拉选择成本中心（端到端项目 / 端到端小车项目 / M57项目 / overseas项目 / G91项目 / 商用车项目），填金额；金额合计必须等于单据总金额，占比自动算
5. 「**上传附件（明细数据）**」上传产出明细表（必须）
6. 提交 → 单据进入"待指派工程师"（等张海霞指派）

### 4.2 财务（张海霞）

1. 「**财务结算**」页
2. **指派工程师**：新单据先点「指派工程师」，选本项目对应的业务工程师（罗桂林 / 彭晓蕾 / 赵晓伟）；指派错了可直接「改派」（改派后原工程师自动退出，不会再看到这条待办）
3. **核算**：点「核算」填扣款、税率 → 系统算应付金额 → 「确认」
4. **统结方提交后**：「财务二次确认」环节核对汇总对比，增幅在 3.5% 内点「确认」
5. 「**催办**」：任何环节卡住时，可在列表行或详情里点「催办」，系统给对方（当前环节处理人）发加急提醒（站内 + 飞书），同一单 10 分钟内只能催一次

### 4.3 业务工程师（罗桂林 / 彭晓蕾 / 赵晓伟）

1. 有指派给你时，收站内/飞书提醒
2. 「**数据验收进度**」→ 待我处理 → 打开单据核对"验收数据明细"与"成本中心"
3. 无误点「确认通过」；有问题点「驳回」并写明原因（整单退回供应商）

### 4.4 统结方（柏川）

1. 收到「待统结方提交」提醒后，打开单据
2. 点「**导入统结数据并提交**」→ 上传/粘贴你的统结明细 → 系统自动汇总金额
3. 提交即完成本环节（金额会与同项目供应商确认合计做对比，对比结果财务可见）
4. 若财务二次确认时提示增幅超限：点「**统结方重新提交**」改正后重提，不必等整单退回

### 4.5 负责人（蔡家辉）/ 算法（马成男）

1. 收到「待负责人确认」/「待算法确认」提醒
2. 「数据验收进度」→ 待我处理 → 核对 → 「确认通过」，或「驳回」并写明原因

### 4.6 OA 结算专员（彭桂苹）

1. 全部环节走完后收到「待OA结算确认」提醒
2. 在 OA 系统完成该单最新结算 → 回平台「数据验收进度」→ 打开单据 → 「确认通过」→ 单据状态变为"已通过"

### 4.7 甲方 PM（周华建）

- **用户管理**：建账号、分配角色（可多角色）、重置密码、禁用账号
- **数据仪表盘**：看累积结算金额、按供应商 / 成本中心 / 结算周期分布
- **系统日志**：查审计（谁在什么时候做了什么）、飞书推送记录
- **催办**：任何环节卡住都可以催办

## 五、运行节奏（建议）

| 时间 | 事项 | 负责人 |
| --- | --- | --- |
| 每月 1–5 日 | 供应商完成上周期数据导入与提交 | 供应商 |
| 每月 6–8 日 | 财务指派工程师 → 业务工程师确认 | 张海霞 / 工程师 |
| 每月 9–10 日 | 财务逐单核算确认 | 张海霞 |
| 每月 11–12 日 | 统结方提交 → 财务二次确认（增幅校验） | 柏川 / 张海霞 |
| 每月 13–14 日 | 负责人、算法确认 | 蔡家辉 / 马成男 |
| 每月 15 日前 | OA 结算确认收尾 | 彭桂苹 |
| 每月 16 日 | 甲方 PM 出结算汇总（数据仪表盘 + 导出对账明细） | 周华建 |

> 周期可按实际结算节奏调整，关键是**每单都走完 7 个环节**，不要跳环节。

## 六、异常与常见问题

| 情况 | 怎么处理 |
| --- | --- |
| 供应商数据填错、已提交 | 谁能驳回谁驳回（写明原因）→ 供应商修正后重新提交；第一环节未开始时供应商可直接编辑/删除 |
| 财务指派错人 | 财务点「改派」选正确的人；系统会自动清掉原工程师的待办并通知他 |
| 某个环节的人迟迟不处理 | 任何人可点「催办」，加急提醒直达当前处理人（站内 + 飞书） |
| 提示"增幅超 3.5% 已拦截" | ①单张单据：核对核算（扣款/税率）是否合理；②统结环节：让统结方「重新提交」改正金额 |
| 成本中心金额合计不等于单据总金额 | 提交会被拦下并显示差额，按差额补齐或调减 |
| 忘密码 | 找管理员（周华建）在「用户管理」里重置，重置后首次登录需改密 |
| 看不到某个页面 | 与角色有关：供应商只看项目管理；数据仪表盘/财务结算给 PM 与财务；用户管理/系统日志仅 PM |
| 想查历史单据/金额 | 「数据仪表盘」看汇总，「财务结算」/「数据验收进度」列表可按项目、供应商筛选，点「导出结算表」导出明细 |

## 七、试行方案

### 7.1 范围
- **试点项目**：建议先选 **1 个真实项目 + 1 个完整结算周期**（如某项目某月）
- **参与人**：本文件第二章名单（7 个环节各 1 人）
- **并轨方式**：平台流程与现有线下确认并行一轮，结果比对一致后再单独走线上

### 7.2 时间表
| 阶段 | 时间 | 内容 | 产出 |
| --- | --- | --- | --- |
| 准备 | D1–D2 | 账号分发、首次登录改密、平台操作宣讲（1 小时） | 每人能独立登录并找到自己的待办 |
| 首轮跑通 | D3–D7 | 选 1 个项目、跑完 7 个环节 | 一张"已通过"的结算单 |
| 复核比对 | D8 | 平台金额 vs 线下核算结果比对 | 差异清单（若有） |
| 复盘 | D9 | 口径/流程问题收集 | 修订项 + 是否扩大试行的结论 |
| 扩大试行 | D10 起 | 按结算周期全量走线上 | 月度结算线上化 |

### 7.3 成功标准（建议）
1. 试点周期内 **7 个环节全部线上走完**，无跳环节；
2. 平台结算金额与线下核算 **一致**（或差异可解释）；
3. 参与者能独立完成本环节操作，不再需要逐一指导；
4. 关键校验生效：金额增幅超限被拦、金额合计不符被拦、未上传附件提交不了；
5. 结算数据可追溯：能查到每单每个环节的确认人、时间、附件。

### 7.4 反馈与支持
- 操作问题：先看本 SOP 第六节；仍不明确找平台管理员
- 口径争议：记录后在第 7.2 节的复盘会上定，定完更新本文件版本号
